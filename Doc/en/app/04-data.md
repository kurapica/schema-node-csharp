# 04. Data Layer

After the runtime resolves a field into `AppFieldType`, the data ultimately has to land in some kind of storage. The App dialect does not bind itself to a specific database; instead, it defines a very thin data access contract, which different Providers implement.

This chapter follows two call chains, `SaveFieldDataAsync` and `QueryDynamicTableAsync`, to explain how dynamic tables are generated, how CRUD is executed, and how transactions and events are connected.

---

## 1. Data Contract

[IAppDataProvider.cs](../../../SchemaNode.App/Data/IAppDataProvider.cs#L11-L61) has only six data methods and three transaction methods:

```csharp
public interface IAppDataProvider
{
    Task<bool> EnsureDynamicTableAsync(DynamicTableSchema schema);

    Task<(IValueAccess? result, int total)> QueryDynamicTableAsync(DynamicTableSchema schema,
        AppSchemaDataResult type, AppSchemaDataFilter? filter = null, int skip = 0, int take = 0,
        bool desc = false, AppSchemaDataOrder[]? orderBy = null, string? dataField = null, bool forUpdate = false);

    Task<(bool result, IValueAccess? update, IValueAccess? origin)> SaveDynamicTableDataAsync(
        DynamicTableSchema schema, IValueAccess? data, bool canAdd = true, bool onlyAdd = false,
        string[]? overrides = null);

    Task<(bool result, IValueAccess? origin)> DeleteDynamicTableDataAsync(DynamicTableSchema schema, AppSchemaDataFilter? filter);
    Task<(bool result, IValueAccess? origin)> ClearDynamicTableDataAsync(DynamicTableSchema schema);
    Task DropDynamicTableAsync(DynamicTableSchema schema);

    Task BeginTransactionAsync();
    Task CommitTransactionAsync();
    Task RollbackTransactionAsync();
}
```

There are two deliberate design choices:

1. **Both input and output are value nodes of `SchemaNode.Node`**, rather than C# POCOs. A Provider does not need to know business types, only to process structures;
2. **There is no "query by SQL" method.** Query conditions are uniformly expressed as `AppSchemaDataFilter`, and each Provider translates them itself.

Return values are uniformly `(result, update, origin)`:

- `update` is the data after this write;
- `origin` is the data before the write.

This provides two snapshots, "before change / after change", for subsequent events, derived computation, and lineage tracking.

## 2. Dynamic Table Structure

`DynamicTableSchema` is the projection of field data on the storage side, generated by [DynamicTable.cs](../../../SchemaNode.App/Data/DynamicTable.cs#L36-L427).

### 2.1 Two Kinds of Tables

```csharp
if (appFieldType is { EnableStorage: false, IsForeignView: false })
{
    Single = true;
    Fields = [];
    return;
}
```

- `Single = true`: single-record table. When the field is not an array, the entire value is treated as one record;
- `Single = false`: multi-record table. When the field is an array of structs with primary keys, each element is one row.

Whether a field is actually persisted is determined by `EnableStorage`; view fields (`IsForeignView`) do not create tables and directly reuse the source field's table.

### 2.2 Scope Fields

```csharp
foreach ((string item, ValueType type, bool isTarget) in targetApp.GetScopeContextItemTypes(context))
{
    fields.Add(new DynamicTableField
    {
        Name = item,
        Type = info.Type,
        MaxLength = info.MaxLength,
        ValueType = type,
        Scope = true,
        Target = isTarget
    });
}
```

Every field table automatically carries the application's scope fields (target, tenant, organization, etc.). This allows the same table to isolate data by target, without business fields having to carry `tenant_id` themselves.

### 2.3 Value Fields and Composite Fields

Generation rules differ by field type:

```text
StructType          → one column per struct field
  ├── Normal field   → column with the same name
  ├── Sub-struct     → {field}_{subfield} composite column
  └── Display field  → try to generate a Join column (see below)
ArrayType<Struct>   → primary key column + normal columns (Single = false)
ArrayType<Scalar>   → _data JSON column
Scalar / Enum       → single _data column
```

Composite columns are joined with `COMPLEX_SEP` (`_`) and recorded via `DataFieldComplexInfo` as `Main` / `Field`; they are restored into a nested structure when read.

### 2.4 Display Fields and Join

`DisplayOnly` fields are not stored, but they can come from other applications. When generating the table structure, the `Default` relation on that field is resolved:

```csharp
var relation = structNode.GetRelations(sField.Name)
    .FirstOrDefault(r => r.ForProperty<Default>() &&
                         r.Process is CallProcess call &&
                         IsReferenceFunc(call.Func));

string? app = call.Args.FirstOrDefault()?.Value?.ToValue<string>();
string? field = call.Args.ElementAtOrDefault(1)?.Value?.ToValue<string>();
string? dataField = call.Args.ElementAtOrDefault(2)?.Value?.ToValue<string>();
...
joins.Add(new DynamicTableJoin { Field = field, Matches = keyMap });
```

See [DynamicTable.cs](../../../SchemaNode.App/Data/DynamicTable.cs#L236-L287).

The generated `DynamicTableField` carries `JoinAppField` / `JoinDataField`, and the Provider is responsible for the association during queries. This is why "cross-table view fields" can participate in queries without copying data.

### 2.5 Table Names

Table naming rules are in [AppFieldType.cs](../../../SchemaNode.App/Runtime/App/AppFieldType.cs#L583-L603):

```csharp
public string DynamicTableName =>
    IsForeignView
    ? View!.AppType?.GetField(View.Field)?.DynamicTableName ?? throw ...
    : !string.IsNullOrWhiteSpace(TableName)
        ? TableName
        : $"{DYNAMIC_TABLE_PREFIX}_{Regex.Replace(App, @"\W+", "_")}_{Name}";
```

- View fields reuse the source field's table;
- An explicit `TableName` takes precedence;
- The default is `dyn_{app}_{field}`, where non-word characters in the application name are replaced with `_`.

Attribute tables (EAV) use the `eav_` prefix and are generated only when `Topology = AttributeBased`.

## 3. Preparing the Table Structure

Before actually executing CRUD, the table must first be ensured to exist. The entry point is [AppDataTableExtension.cs](../../../SchemaNode.App/Data/AppDataTableExtension.cs#L13-L58):

```csharp
internal static async Task<DynamicTableSchema> PrepareFieldDataAsync(this SchemaContext context, AppFieldType field)
{
    if (!field.EnableDynamicTable) return field.GetDynamicTableSchema(context);

    DynamicTableSchema? schema = field.GetItem<DynamicTableSchema>();
    if (schema != null) return schema;

    IAppDataProvider dataProvider = context.GetService<IAppDataProvider>() ?? throw ...;
    using ICriticalRegion locker = await context.GetLockAsync($"SCHEMA_CONTEXT_DYN_TABLE_CREATION:{field.DynamicTableName}");
    try
    {
        schema = field.GetItem<DynamicTableSchema>();
        if (schema != null) return schema;

        schema = field.GetDynamicTableSchema(context);
        if (field.IsForeignView)
        {
            AppFieldType foreignField = (await context.GetAppTypeAsync(field.View!.App))?.GetField(field.View.Field) ?? throw ...;
            await context.PrepareFieldDataAsync(foreignField);
        }
        else
        {
            await dataProvider.EnsureDynamicTableAsync(schema);
            if (schema.Joins is { Length: > 0 })
                foreach (DynamicTableJoin join in schema.Joins)
                    await context.PrepareFieldDataAsync(field.Application.GetField(join.Field)!);
        }
        return schema;
    }
    ...
}
```

This code solves three problems:

- **Create only once**: `GetItem<DynamicTableSchema>()` acts as a cache, with double-checking;
- **Concurrency safety**: `ICriticalRegionProvider` locks by table name, avoiding concurrent table creation;
- **Dependencies first**: view fields prepare the source field first, and Join fields prepare the associated field first.

> Note that `ICriticalRegion` is not a database lock, but an in-process/distributed critical region. It can be replaced by implementations such as Redis or ZooKeeper.

## 4. CRUD Chain

The entry points for CRUD are extension methods on `SchemaContext`, defined together in [AppDataTransactionExtension.cs](../../../SchemaNode.App/Data/AppDataTransactionExtension.cs).

### 4.1 Save

```csharp
public static async Task<bool> SaveFieldDataAsync(this SchemaContext context, AppFieldType field,
    IValueAccess? value = null, bool innerCall = false, bool canAdd = true, bool onlyAdd = false, string[]? overrides = null)
{
    if (!field.EnableDynamicTable || field.IsForeignView) return false;
    if (field.PushSource != null && !innerCall) return false;

    var dataProvider = context.GetService<IAppDataProvider>() ?? throw ...;
    DynamicTableSchema schema = await context.PrepareFieldDataAsync(field);

    (bool result, IValueAccess? update, IValueAccess? origin) =
        await dataProvider.SaveDynamicTableDataAsync(schema, value, canAdd, onlyAdd, overrides);

    if (result) OnFieldDataChanged(context, field, TransactionChangeOperation.Modify, update, origin);
    return result;
}
```

See [AppDataTransactionExtension.cs](../../../SchemaNode.App/Data/AppDataTransactionExtension.cs#L35-L57).

Three preconditions are worth noting:

| Condition | Meaning |
| --- | --- |
| `!field.EnableDynamicTable` | Fields that are not persisted cannot be written |
| `field.IsForeignView` | View fields are read-only |
| `field.PushSource != null && !innerCall` | Derived fields can only be written by the push flow |

`OnFieldDataChanged` records the change into a context item of the current transaction instead of raising an event immediately. This avoids the situation where "the transaction rolled back, but the event has already been emitted".

### 4.2 Clear and Delete

```csharp
public static async Task<bool> ClearFieldDataAsync(...)
{
    ...
    (bool result, IValueAccess? origin) = await dataProvider.ClearDynamicTableDataAsync(schema);
    if (result) OnFieldDataChanged(context, field, TransactionChangeOperation.DropAll, null, origin);
}

public static async Task<bool> DeleteFieldListDataAsync(this SchemaContext context, AppFieldType field, AppSchemaDataFilter filter)
{
    ...
    (bool result, IValueAccess? origin) = await dataProvider.DeleteDynamicTableDataAsync(schema, filter);
    if (result) OnFieldDataChanged(context, field, TransactionChangeOperation.Delete, null, origin);
}
```

See [AppDataTransactionExtension.cs](../../../SchemaNode.App/Data/AppDataTransactionExtension.cs#L59-L142).

`DeleteSchemaNodeAsync` (in `AppDataProviderExtension`) is responsible for converting value nodes into filter conditions and handling multi-primary-key combinations:

```text
Node count <= MAX_COMBINE_CASE_COUNT
  → convert each node to AppSchemaDataFilter, then combine with OrElse

Node count >  MAX_COMBINE_CASE_COUNT
  → first collect an IN list by primary key for the query, then filter precisely in memory by composite primary key
```

See [IAppDataProvider.cs](../../../SchemaNode.App/Data/IAppDataProvider.cs#L71-L194).

This avoids generating excessively long `OR` conditions.

### 4.3 Transactions and Events

```csharp
public static async Task BeginTransactionAsync(this SchemaContext context)
{
    var dataProvider = context.GetService<IAppDataProvider>() ?? throw ...;
    await dataProvider.BeginTransactionAsync();
    context.SetContextItem(new Dictionary<string, TransactionChangeData>());
}

public static async Task CommitTransactionAsync(this SchemaContext context, bool noEvent = false)
{
    var transChangedData = context.GetOrAddContextItem<Dictionary<string, TransactionChangeData>>();

    // Process data field push
    foreach (string target in transChangedData.Keys.ToArray())
        await ProcessDataPush(context, target, transChangedData[target]);

    await dataProvider.CommitTransactionAsync();

    if (noEvent) return;

    foreach (var (target, value) in transChangedData)
        foreach (var (field, changes) in value.Changes)
            foreach (var change in changes)
                ... RaiseEvent(AppFieldDataCreateEvent/UpdateEvent/DeleteEvent ...)
}
```

See [AppDataTransactionExtension.cs](../../../SchemaNode.App/Data/AppDataTransactionExtension.cs#L151-L300).

The order is fixed:

```text
1. Data push        (derived fields computed first)
2. Commit database
3. Raise data events (workflows and external subscribers are notified here)
```

This also explains why a workflow can start based on the "data created" event: events are raised only after the transaction succeeds.

## 5. Entity: Storing Application Definitions with Application Data

The types under `Data/Entity` are the "metadata tables" of the App dialect:

| Entity | Corresponding definition |
| --- | --- |
| `AppEntity` | `AppSchema` |
| `AppFieldEntity` | `AppFieldSchema` |
| `AppWorkflowEntity` | `AppWorkflowSchema` |
| `NodeEntity` | `NodeSchema` |
| `EnumValueEntity` | Enum cascade child items |

See [AppEntity.cs](../../../SchemaNode.App/Data/Entity/AppEntity.cs#L13-L59):

```csharp
[Meta<App>(NS_SYSTEM_SCHEMA)]
[Meta<EnableStorage>(true)]
internal class AppEntity
{
    [Meta<PrimaryIndex>(0)]
    public string? Container { get; set; }

    [Meta<PrimaryIndex>(1)]
    public string Name { get; set; }

    public JsonObject? Extensions { get; set; }
}
```

Explicit conversion operators handle the conversion between Entity and Schema:

```csharp
public static implicit operator AppEntity?(AppSchema? appSchema) => new AppEntity
{
    Container = string.IsNullOrWhiteSpace(appSchema.Container) ? ROOT : appSchema.Container,
    Name = appSchema.Name,
    Extensions = appSchema.Extensions?.DeepClone() as JsonObject,
};
```

Note that `Extensions` stores all extension properties (display, auths, view, ...) instead of expanding them into columns. This way, adding a Property does not require changing the table structure.

`EntityExtension` in turn wraps "query by primary key" and "query by condition" into C# expressions:

```csharp
AppSchemaDataFilter filter = AppSchemaDataFilterVisitor.Build(cond);
using var stack = context.StackAccess(appFieldType.App, target);
var (value, _) = await context.GetAppFieldDataAsync(appFieldType, AppSchemaDataResult.First, filter, ...);
```

See [EntityExtension.cs](../../../SchemaNode.App/Data/EntityExtension.cs#L22-L66).

`StackAccess(app, target)` pushes the target into the access context, so Entity queries are automatically constrained by scope and target isolation as well.

## 6. Provider Implementations

### 6.1 In-Memory Implementation

[InMemoryAppDataProvider.cs](../../../SchemaNode.App/Data/InMemoryAppDataProvider.cs#L11-L84) is used for testing:

```csharp
ConcurrentDictionary<string, List<IValueAccess>> table = _dynamicTables.GetOrAdd(schema.AppField.DynamicTableName, _ => []);
List<IValueAccess> list = table.GetOrAdd(compositeKey, _ => []);
```

- Uses "table name + scope key" as the composite key;
- Filtering directly calls `filter.Test(schemaContext, node)`;
- Supports six result forms, `Count / Exist / First / Last / Field / List`, consistent with the interface semantics.

It is the best reference implementation for understanding the semantics of `IAppDataProvider`.

### 6.2 SQL Implementation

SQL databases are composed through two interfaces:

```csharp
public interface IAppDataSqlProvider<T>: IAppDataProvider where T: ISqlProvider;
```

See [IAppDataSqlProvider.cs](../../../SchemaNode.App/Data/Sql/IAppDataSqlProvider.cs#L1-L7).

`ISqlProvider` is responsible only for dialect differences:

```text
QuoteField / QuoteTable / QuoteIndex
GenParameterName
Literal
Binary / Arithmetic
LikeContains / LikeStartsWith / LikeEndsWith
In / NotIn / IsNull / IsNotNull
```

See [ISqlProvider.cs](../../../SchemaNode.App/Data/Sql/ISqlProvider.cs#L11-L80) and [DefaultSqlProvider.cs](../../../SchemaNode.App/Data/Sql/DefaultSqlProvider.cs#L8-L59).

When registering, `AddAppDataProvider<T>` automatically detects `IAppDataSqlProvider<>` and instantiates the corresponding `ISqlProvider`:

```csharp
Type? interfaceType = typeof(T).GetInterfaces().FirstOrDefault(i => i.IsSubclassOfGenericType(typeof(IAppDataSqlProvider<>)));
if (interfaceType != null)
{
    ISqlProvider instance = (ISqlProvider)Activator.CreateInstance(interfaceType.GetGenericArguments()[0])!;
    services.AddSingleton(instance);
}
```

See [AppService.cs](../../../SchemaNode.App/Service/AppService.cs#L35-L50).

## 7. Summary

```text
AppFieldType
  ↓
DynamicTableSchema
  ├── scope fields
  ├── primary key / value fields
  ├── composite fields
  ├── DisplayOnly → Join
  └── table names / EAV tables
  ↓
PrepareFieldDataAsync (critical region + dependency recursion)
  ↓
IAppDataProvider
  ├── Query   → AppSchemaDataResult
  ├── Save    → (update, origin)
  ├── Delete  → filter conditions
  └── Clear / Drop
  ↓
CommitTransaction
  ├── ProcessDataPush
  ├── Commit
  └── Raise AppFieldData*Event
```
