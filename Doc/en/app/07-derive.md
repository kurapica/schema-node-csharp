# 07. Views, Foreign Keys, and Derive

Fields in an App are not isolated. A field can:

- display another field's data (`View`);
- take another app's target as a foreign key (`Foreigns`);
- be computed from a source field (`DataDerive`).

All three are declared at the definition layer, build dependencies while loading, and propagate along those dependencies when data changes. This chapter follows these three chains.

---

## 1. Division of Responsibilities

```text
View
  Read-only display, no data copied, reuses the source table

Foreigns
  References another app's target, participates in queries/validation

DataDerive
  Computes from source fields and writes into its own table, supports cross-field lineage
```

They solve different problems, and therefore carry different constraints:

| Mechanism | Writes to storage | Cross-app | Change propagation |
| --- | --- | --- | --- |
| View | No (reuses the source table) | Yes | None, read in real time |
| Foreigns | Yes (foreign key column) | Yes | None |
| DataDerive | Yes (result table) | Yes | Observer chain + incremental push |

---

## 2. View: Cross-App View Fields

### 2.1 Definition

[View.cs](../../../SchemaNode.App/Property/App/View.cs#L21-L77):

```csharp
[Meta<Static>(true)]
[Relation<InVisible, Call>(nameof(View), NS_SYSTEM_LOGIC_EQ, $"@{nameof(EnableStorage)}", true)]
[Relation<Default, Call>($"{nameof(View)}.{nameof(FieldView.Owner)}", ..., $"@{nameof(App)}")]
public class View : Property<FieldView>;

public sealed class FieldView
{
    public string Owner { get; set; }
    public string App { get; set; }
    public string Field { get; set; }
    public string? FieldType { get; set; }
    public string? Map { get; set; }
}
```

Several constraints are written directly on the relations:

- `InVisible`: the view configuration is invisible when `EnableStorage == true`. A view field is not persisted, so storage must be turned off;
- `Owner` defaults to the current app, and is used to exclude the app's own fields;
- The candidates for `Field` come from `getappforeignfields(App, Owner)`, that is, the fields in the source app that "can serve as view sources";
- `FieldType` is derived automatically from the source field and is invisible to users;
- `Map` is visible only when the source app is **not** `SystemLevel`; it maps the source field to the target field name in the current app (a system-level app has no target, so no mapping is needed).

### 2.2 Why Views Do Not Copy Data

A view field has no table of its own. `DynamicTableName` returns the source field's table directly:

```csharp
public string DynamicTableName =>
    IsForeignView
    ? View!.AppType?.GetField(View.Field)?.DynamicTableName ?? throw ...
    : ...
```

See [AppFieldType.cs](../../../SchemaNode.App/Runtime/App/AppFieldType.cs#L583-L603).

Therefore a query on a view field ultimately lands on the source table; scope, target, and permissions all follow the source field.

### 2.3 Load-Time Validation

`AppFieldType.LoadAsync` validates the view structure:

```csharp
if (f.DisplayOnly == true)
{
    RelationType? relation = structType.GetRelations(f.Name).FirstOrDefault(r => r.ForProperty<Default>());
    if (relation is not { Process: CallProcess call } || ...)
        Error ??= AppErrorCodes.APP_FIELD_VIEW_NOT_VALID;
}
else if (sourceStruct.GetField(f.Name) is { Type: not null } sourceFieldMatch)
{
    if (!sourceFieldMatch.Type.IsAssignableTo(f.Type))
        Error ??= AppErrorCodes.APP_FIELD_VIEW_NOT_VALID;
}
```

See [AppFieldType.cs](../../../SchemaNode.App/Runtime/App/AppFieldType.cs#L335-L402).

The meaning is:

- A `DisplayOnly` field must be generated by a relation and cannot be defined by hand;
- For a non-`DisplayOnly` field, if the source field exists, the types must be compatible.

## 3. Foreigns: Foreign Keys

[Foreigns.cs](../../../SchemaNode.App/Property/App/Foreigns.cs#L19-L51):

```csharp
[Meta<Static>(true)]
[Relation<InVisible, Relation.Call>(nameof(Foreigns), NS_SYSTEM_LOGIC_NOT, $"@{nameof(EnableStorage)}")]
[Relation<BlackList, Relation.Call>($"{nameof(Foreigns)}.{nameof(Foreign.App)}",
    NS_SYSTEM_COLLECTION_NEWARRAY, $"@{nameof(AppFieldSchema.App)}")]
public class Foreigns : Property<Foreign[]>;

public sealed class Foreign
{
    [Meta<SchemaType>(typeof(AppType))]
    public string App { get; set; }

    [Meta<SchemaType>(typeof(Identifier))]
    public string Field { get; set; }
}
```

- A foreign key must be persisted, so it is invisible when `EnableStorage = false`;
- The blacklist of `App` excludes the current app, preventing self-references;
- `Field` points to the **target field** of another app.

Load-time validation:

```csharp
if (string.IsNullOrWhiteSpace(foreign.Field) || string.IsNullOrWhiteSpace(foreign.App) ||
    await context.GetAppTypeAsync(foreign.App) is not { } refApp ||
    refApp.ScopeType == AppScopeType.SystemLevel ||
    structType?.GetField(foreign.Field) == null)
{
    Error ??= AppErrorCodes.APP_FIELD_FOREIGN_NOT_VALID;
}
```

The referenced app cannot be `SystemLevel`, because a system-level app has no target and cannot serve as a foreign key target.

In the demo, a foreign key's role is to "provide a candidate list for entry", for example offering the user list or the venue list as options for a participant field. It does not participate in back-end relation operations, as also noted in tryit.

## 4. DataDerive: Computing from Source Fields

### 4.1 Definition

[DataDerive.cs](../../../SchemaNode.App/Property/App/DataDerive.cs#L34-L144):

```csharp
[Meta<Static>(true)]
[Relation<InVisible, Call>(nameof(DataDerive), NS_SYSTEM_LOGIC_NOT, $"@{nameof(EnableStorage)})")]
[Relation<Default, Call>($"{nameof(DataDerive)}.{nameof(Derive.SourceType)}",
    $"{NS_SYSTEM_SCHEMA_REFLECT_APP}.{nameof(SystemReflectApp.getappfieldtype)}", $"@{nameof(App)}", $"@{nameof(DataDerive)}.{nameof(Derive.Source)}", true)]
public class DataDerive : Property<Derive>;

public class Derive
{
    public string Source { get; set; }
    public string? FieldType { get; set; }
    public string? SourceType { get; set; }

    [Meta<SchemaType>(typeof(FuncType))]
    [Relation<Valid, Assign>(NS_SYSTEM_SCHEMA_REFLECT_FUNC_WITH_ARGS, NODE_SELF, $"@{nameof(SourceType)}")]
    [Relation<Valid, Assign>(NS_SYSTEM_SCHEMA_REFLECT_FUNC_WITH_RETURN, NODE_SELF, $"@{nameof(FieldType)}", true)]
    public string Calc { get; set; }

    public DataCombineType? Combine { get; set; }
    public FieldCombine[]? Combines { get; set; }
}
```

Four semantic slots:

```text
Source       source field (within the same app)
Calc         calculation function, parameter type = SourceType, return type = FieldType
Combine      aggregation mode for scalars/enums
Combines     per-field aggregation mode for structs
```

The type constraints on `Calc` are not decoration; they are genuinely checked at compile time: the parameters must accept the source field, and the return value must be assignable to the target field.

### 4.2 Aggregation Modes

The semantics of `DataCombineType` are implemented in [DataDerive.cs](../../../SchemaNode.App/Property/App/DataDerive.cs#L153-L237):

```csharp
DataCombineType.Newest → take the last one
DataCombineType.Oldest → take the first one
DataCombineType.Sum    → numeric sum
DataCombineType.Count  → count
```

For arrays of structs, `GroupJoinObjectMap` merges by primary key:

```csharp
if (keyMap.TryGetValue(key, out StructNode? total))
{
    keyCount[key]++;
    foreach (string s in valueFields)
    {
        switch (joinMethodMap.GetValueOrDefault(s, DataCombineType.Newest))
        {
            case DataCombineType.Newest: ...
            case DataCombineType.Oldest: ...
            case DataCombineType.Sum: ...
            case DataCombineType.Count: ...
        }
    }
}
```

See [DataDerive.cs](../../../SchemaNode.App/Property/App/DataDerive.cs#L242-L326).

> The "Organizer attendance summary" in the demo is exactly `Combine = Count`: it uses `orgnizer` as the primary key and counts participants.

### 4.3 Compile Time: Where Lineage Comes From

The function of a derived field is not free to query whatever it likes at runtime. So that the system knows **which changes trigger a recomputation**, the compile phase analyses the function's expression tree.

`DataDeriveCompileContext` is defined in [DataDeriveCompileContext.cs](../../../SchemaNode.App/Runtime/Compile/CompileContext/DataDeriveCompileContext.cs#L13-L124):

```csharp
public class DataDeriveCompileContext(SchemaContext context, FunctionType function) : CompileContext(context, function)
{
    private readonly List<DataDeriveThirdFieldInfo> _thirdFields = [];
    public DataDeriveThirdFieldInfo[] ThirdFields => _thirdFields.ToArray();
    ...
}
```

It does two things.

**First, it identifies third-party fields.**

```csharp
case $"{NS_SYSTEM_DATA_APP}.{nameof(SystemAppData.getfield)}":
{
    if (funcCallExp.ApplyMode == ApplyMode.Call && ...)
    {
        _appType ??= await Context.GetAppTypeAsync(appExp.Value.GetValue<string>()!);
        var thirdField = _appType.GetField(fieldExp.Value.GetValue<string>() ?? string.Empty);
        if (thirdField?.ValueType is not ArrayType { Element: StructType arrayStruct, Primary: { Count: > 0 } } arrayType) break;
        ...
        _thirdFields.Add(thirdFieldInfo);
    }
}
```

Whenever `system.data.app.getfield('app', 'field', ...)` appears in the function, that third field is recorded as a `DataDeriveThirdFieldInfo`.

**Second, it requires the primary key to come from parameters or constants.**

```csharp
foreach (StructFieldExp field in toStruct.Fields)
{
    if (array.Primary.Contains(field.Name, StringComparer.OrdinalIgnoreCase))
    {
        bool fromValid = false;
        SchemaExp? keyExp = field.Expression;
        while (keyExp != null)
        {
            switch (keyExp)
            {
                case VariableExp varExp: keyExp = varExp.Value; break;
                case FieldAccessExp fieldAccessExp:
                    SchemaExp owner = fieldAccessExp.Owner;
                    if (owner is ArgumentExp argExp)
                    {
                        keyExp = null; fromValid = true;
                        if (argExp.Index > 0)
                        {
                            DataDeriveThirdFieldInfo fldInfo = _thirdFields.First(a => a.Arg == argExp);
                            if (!fldInfo.PushKeys.Contains(fieldAccessExp.FieldName))
                                fldInfo.PushKeys.Add(fieldAccessExp.FieldName);
                        }
                    }
                    else throw new FunctionVisitException(AppErrorCodes.FUNC_IS_NOT_PUSH_FUNC);
                    break;
                case ConstantExp: keyExp = null; fromValid = true; break;
                default: throw new FunctionVisitException(AppErrorCodes.FUNC_IS_NOT_PUSH_FUNC);
            }
        }
        if (!fromValid) throw new FunctionVisitException(AppErrorCodes.FUNC_IS_NOT_PUSH_FUNC);
    }
    else if (FromThirdField(field.Expression))
    {
        throw new FunctionVisitException(AppErrorCodes.FUNC_IS_NOT_PUSH_FUNC);
    }
}
```

See [DataDeriveCompileContext.cs](../../../SchemaNode.App/Runtime/Compile/CompileContext/DataDeriveCompileContext.cs#L149-L200).

The meaning of this validation is:

- The primary key of the result must be determinable from input parameters or constants;
- The primary key must not come from a third-party field, otherwise it is impossible to infer "which source record changed";
- A non-primary-key field coming from a third-party field is likewise forbidden (otherwise incremental updates cannot be guaranteed).

This is exactly what the demo mentions: **the venue ID is obtained through a specific semantic function, and the key is explicit in the call, so the system can register the lineage.**

### 4.4 Runtime: Observers and Push

When a field is loaded, `DataDerive` is parsed into an observer chain:

```csharp
PushFunc = funcNode;
AppFieldType? pushSource = Application.GetField(derive.Source);
pushSource.AddObserver(this);
PushSource = pushSource;

DataDeriveCompileContext compileContext = new DataDeriveCompileContext(context, funcNode);
FunctionTypeSchema pushSchema = await compileContext.VisitFunctionType();
if (compileContext.ThirdFields.Length > 0)
{
    ThirdPushFields = compileContext.ThirdFields;
    foreach (DataDeriveThirdFieldInfo push in compileContext.ThirdFields)
        Application.GetField(push.Field)?.AddObserver(this);
}
PushFuncSchema = pushSchema;
```

See [AppFieldType.cs](../../../SchemaNode.App/Runtime/App/AppFieldType.cs#L260-L310).

The resulting dependency graph is:

```text
Source field ──AddObserver──→ derived field
Third-party field ──AddObserver──→ derived field
```

Note that the observer relationship is **reversed**. A field does not know what it depends on; it only knows "who is observing me". During a push, propagation starts from the changed field and spreads outward along `Observers`.

## 5. Incremental Push

A data change does not immediately recompute all derived fields. When the transaction commits, `ProcessDataPush` computes step by step along the dependency levels.

### 5.1 Generating Push Levels

```csharp
List<AppFieldType> baseFields = changeData.Changes.Keys.Where(p => p.HasObserver).ToList();

FieldDataPushLevel? root = null;
FieldDataPushLevel? curr = null;
Dictionary<AppFieldType, FieldDataPushLevel> updateFieldsLvlMap = new();

while (baseFields.Count > 0)
{
    FieldDataPushLevel next = new();

    foreach (AppFieldType node in baseFields.Where(p => p.HasObserver)
                 .SelectMany(p => p.Observers!).Distinct()
                 .Where(n => n is { EnableDynamicTable: true, IsForeignView: false }))
    {
        if (!updateFieldsLvlMap.TryGetValue(node, out FieldDataPushLevel? value))
        {
            next.Fields.Add(node);
            updateFieldsLvlMap.Add(node, next);
        }
        else
        {
            next.Fields.Add(node);
            value.Fields.Remove(node);
            updateFieldsLvlMap[node] = next;
        }
    }

    if (next.Fields.Count <= 0) break;
    ...
    baseFields = next.Fields.Where(p => p.HasObserver).ToList();
}
```

See [AppDataTransactionExtension.cs](../../../SchemaNode.App/Data/AppDataTransactionExtension.cs#L350-L422).

A few details:

- Only fields with `HasObserver` are processed;
- Only fields that are actually persisted and are not views are processed;
- A field depended on by several upstream fields is moved to a **lower** level, ensuring that all upstream fields are computed first;
- Levels are chained through `FieldDataPushLevel.Next`.

### 5.2 Collecting Changes

Each derived field collects three kinds of data, keyed by primary key:

```text
Origins   before the change
Updates   after the change
UnChanged unchanged but referenced
```

Third-party fields go through the same flow:

```csharp
foreach (DataDeriveThirdFieldInfo thirdInfo in field.ThirdPushFields)
{
    if (thirdInfo.PushKeys.Count == 0)
    {
        context.LogWarning($"The third push field {thirdInfo.Field} ... has no push keys, skip ...");
        continue;
    }

    AppFieldType? thirdAppField = field.Application.GetField(thirdInfo.Field);
    if (thirdAppField == null) continue;
    GatherFieldChangeInfos(thirdAppField, thirdInfo);
}
```

See [AppDataTransactionExtension.cs](../../../SchemaNode.App/Data/AppDataTransactionExtension.cs#L433-L466).

`PushKeys` are the primary key fields recorded at compile time. Without them, the system cannot determine which row of the third-party field changed, and can only skip.

### 5.3 Computing Old and New Results

```csharp
List<IValueAccess?[]> originsPush = InitPushData(pushSourceChangeInfo.Origins.Values, pushSourceChangeInfo.UnChanged.Values);
List<IValueAccess?[]> updatesPush = InitPushData(pushSourceChangeInfo.Updates.Values, pushSourceChangeInfo.UnChanged.Values);

await FillPushData(originsPush, true);
await FillPushData(updatesPush);

ArrayNode oldResult = await CalcPushData(originsPush);
ArrayNode newResult = await CalcPushData(updatesPush);

await context.SaveIncrementalData(field, newResult, oldResult);
```

See [AppDataTransactionExtension.cs](../../../SchemaNode.App/Data/AppDataTransactionExtension.cs#L586-L617).

Why compute both the "old result" and the "new result" here?

Because an aggregated result may **migrate**:

```text
Change Ann's venue
  → the old venue's count -1
  → the new venue's count +1
```

Computing only the new result cannot tell that the old venue needs to be decremented. Therefore the two must be computed as a pair, and `SaveIncrementalData` then performs a differential write.

This matches the observation in the demo: after changing Ann's venue, the "Organizer attendance summary" stays the same, while the "Venue summary" shifts.

### 5.4 Loading Data for Third-Party Fields

If the referenced third-party data is not in the current change set, it must be fetched before computing:

```csharp
ArrayNode? fetchData = await context.GetSchemaDataAsync(thirdAppField.App, fromField.Name,
    target, AppSchemaDataResult.List, filter) as ArrayNode;
if (fetchData == null) continue;

DynamicTableSchema schema = fromField.GetDynamicTableSchema(context);
foreach (IValueAccess node in fetchData)
{
    if (node is not StructNode structNode) continue;
    string? key = schema.GetPrimaryKey(structNode);
    if (string.IsNullOrEmpty(key)) continue;
    if (tarChangeInfo.Origins.ContainsKey(key) || tarChangeInfo.Updates.ContainsKey(key)) continue;
    tarChangeInfo.UnChanged[key] = structNode;
}
```

See [AppDataTransactionExtension.cs](../../../SchemaNode.App/Data/AppDataTransactionExtension.cs#L565-L583).

If composite primary keys could produce too many combinations, the query degrades to several `IN` conditions to avoid generating an excessively long `OR`:

```csharp

{

    {
        ArrayNode? keysNode = CombineField(changeInfos, map.Key);
        ...
        kFilter = new AppSchemaDataFilterBinary(LogicType.Contains,
            new AppSchemaDataFilterValue(keysNode),
```

## 6. Where the Three Mechanisms Execute

```text
            View                       Foreigns             DataDerive
Definition  FieldView                  Foreign[]            Derive
Loading     validate structure         validate target app  compile function, register observer
Storage     none, reuses source table  foreign key column   separate result table
Query       via the source table       Join / validation    ordinary table query
Write       forbidden                  ordinary writes      push writes only
Change      —                          —                    observer chain + paired old/new computation
```

In the tryit demo:

- `users` and `venues` are view fields → `View`;
- the participant's `orgnizer` selection → `Foreigns`;
- `Organizer attendance summary` → `DataDerive` + `Combine.Count`;
- `Venue attendance summary` → `DataDerive` + third-party field `getfield` + lineage tracing.

---

## 7. Summary

The core of the derive layer is not "how to compute", but "**how to know what to recompute**".

```text
DataDerive
  ├── compile time: parse the function, record source field / third-party field / primary key mapping
  ├── load time: build the observer chain
  ├── transaction commit: start from changed fields and spread along dependency levels
  └── computation: compute old and new results as a pair, write differentially
```

View and Foreigns are lighter mechanisms: one reuses the source table, the other merely references a target. Together, the three turn fields into a traceable semantic network, rather than hand-written synchronization logic scattered through business code.
