# 04. Enum Prototype

The enum prototype describes a finite set of named values. Unlike ordinary scalars, an enum not only has actual data values (`string`, `int`, or `Flags`), but can also organize these values into an accessible entry tree for execution layers to query, cascade-select, and validate.

The relevant implementation is concentrated in four places:

- `Schema/EnumSchema.cs`: declarations of the enum prototype, definition body, and usage form;
- `Runtime/Type/EnumType.cs`: runtime implementation of the enum type;
- `Node/EnumNode.cs`: enum value node;
- `Generator/EnumGenerator.cs`: generating Schema from C# enums.


## 1. Prototype Declaration

```csharp
[Meta<SchemaKind>(SCHEMA_KIND_NODE_ENUM, SCHEMA_KIND_ORDER_ENUM)]
[Meta<NodeKind>(NODE_KIND_ENUM, SCHEMA_KIND_ORDER_ENUM)]
[Meta<NodeValueKind>(NODE_KIND_ENUM, SCHEMA_KIND_ORDER_ENUM)]
[Meta<NodeType>(typeof(RuntimeEnumType))]
[Meta<SchemaUsage>(typeof(EnumUsage))]
[Meta<SchemaGenerator>(typeof(EnumGenerator))]
[Meta<Append>(typeof(EntrySource), typeof(Default), typeof(BlackList), typeof(WhiteList), typeof(Valid))]
[Meta<EnumValue>]
public sealed class EnumKind;
```

Through metadata, `EnumKind` declares the enum's prototype identifier, node classification, runtime type, usage form, and generator, while also specifying the semantic properties the enum supports.

Among them, `NodeKind` and `NodeValueKind` describe the node classification and value classification respectively; `NodeType` specifies the runtime implementation; and `SchemaUsage` and `SchemaGenerator` associate the enum's usage form and the C# enum generation mechanism respectively.

These metadata are linked to concrete implementations through the prototype registration mechanism. Readers can follow the declarations directly to the corresponding code, and there is no need to expand each item in the documentation.


## 2. Enum Definition Body

The enum definition body is described by `EnumSchema`, and contains three fields:

- `Type`: specifies the value type of the enum.
- `Values`: defines the enum entries.
- `Cascade`: provides a description for each cascade level, and also limits the maximum cascade depth.

### Value Types and Entries

`Type` supports three forms:

| Type | Value type | Typical use |
|---|---|---|
| `String` | `string` | Enums with named values |
| `Int` | `long` | Enums using integer numbering |
| `Flags` | `long` | Composable bit flags |

`Values` describes entries using `Entry<string>[]`. `Entry` is attached with the `node.entry` prototype, which provides a unified cascade description. In addition to the actual value, each entry can also carry display properties such as `display`, as well as other entry properties supported by the execution layer.

For example:

```json
{
  "namespace": "example",
  "name": "gender",
  "kind": "enum",
  "enum": {
    "type": "string",
    "values": [
      {
        "value": "unknown",
        "display": { "key": "unknown", "trans": [ { "lang": "en", "tran": "Unknown" }] }
      },
      {
        "value": "male",
        "display": { "key": "male", "trans": [ { "lang": "en", "tran": "Male" }] }
      },
      {
        "value": "female",
        "display": { "key": "female", "trans": [ { "lang": "en", "tran": "Female" }] }
      }
    ]
  }
}
```

The structure of `display` is somewhat special, used for localized display text. If another display approach is preferred, the `Invisible` property can simply be set to true for the `Display` property; semantic properties can themselves also have property descriptions.


## 3. Enum Usage Form

`EnumUsage` does not redefine enum values, but describes the selection rules in a particular usage scenario. It supports properties such as whitelist, blacklist, root node, cascade depth, leaf-only selection, and single bit-flag selection. These cannot be specified when defining the enum type, and must be determined according to the usage scenario. For example, in the diagram below, all enum values are of the same type, but different selections are made based on properties.

![Cascade](../tryit/pic/01_type_007.png)

In addition to declaring the available properties, the dependencies between these properties are also declared. For example, `WhiteList` and `BlackList` can affect the default value, the candidate entries of `Root` are dynamically computed from the enum definition, and `CascadeDepth` controls the cascade depth.


## 4. Runtime and C# Enum Generation

`EnumType` is responsible for loading enum definitions and organizing the entries into a queryable entry tree.

`EnumNode` represents an actual enum value. Internally, it stores a string or integer value according to the enum type, and provides the ability to compare with the corresponding scalar node.

`EnumGenerator` can generate Schema from C# enums. For ordinary C# enums, a string enum is generated by default, with entry values preferring the name specified by `EnumMember`, or otherwise the field name converted to camelCase; enums with `[Flags]` generate bit-flag enums using the actual numeric values of the fields.

The display text of entries can be generated from XML documentation summaries, and metadata on fields can also be generated together with the entries. For ordinary enums that need integer numbering, this can be declared directly in the Schema.

The specific generation rules and runtime processing can be further understood from the implementations of `EnumGenerator`, `EnumType`, and `EnumNode`.

## 5. Summary

The enum prototype organizes a finite set of values into three cooperating parts:

- The **definition body** describes the value type, the entry set, and their semantic properties;
- The **usage form** describes the candidate range and selection rules in the current scenario;
- The **runtime** provides entry access, value processing, and external data source integration capabilities.

This makes an enum more than a set of static constants: it can support different usage scenarios through semantic properties and relation mechanisms, and be accessed at runtime through a unified entry structure. At the same time, semantics and C# types are defined together, which is also how the same semantics is maintained as the single source of truth.
